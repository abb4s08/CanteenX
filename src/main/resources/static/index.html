CanteenX Academic Demo Tour 🧭

Evaluation Workflow Guide:

  1. Step 1 (Student Ordering): Sign in as student@canteenx.local / student123. Select REC Cafe, add items to cart, test single-canteen cart protection by attempting to switch to REC Hut, complete checkout with simulated UPI, and observe the high-contrast digital token (e.g. CAF-0000001).
  2. Step 2 (Counter Handover): Sign in as REC Cafe Counter (cafe@canteenx.local / cafe123). Enter the token code. Observe order verification, ordered items, and click "Confirm Handover". Test duplicate redemption rejection by entering the same token again.
  3. Step 3 (Counter Isolation): Attempt to verify a REC Hut token (HUT-0000001) from the REC Cafe counter. Observe backend authorization rejection (Access Denied: belongs to another outlet).
  4. Step 4 (Admin Intelligence): Sign in as admin@canteenx.local / admin123. View live revenue KPIs, outlet metrics, best-selling dishes, create/edit dishes, review the audit log, and download the sales CSV report.

OOP & DBMS Concepts Demonstrated:

  • Encapsulation & Abstraction: Service layer hides direct SQL and manages ACID transaction boundaries.
  • Inheritance & Polymorphism: Abstract User hierarchy (Student, Shopkeeper, Admin); polymorphic PaymentStrategy implementations.
  • DBMS Concurrency: SELECT ... FOR UPDATE on token_counters guarantees unique sequential token codes under simultaneous student requests.
  • Atomic Redemption: Conditional UPDATE ... WHERE order_status='PLACED' guarantees no token can be handed over twice.
